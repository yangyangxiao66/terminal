# 终端矩阵

Windows 桌面终端复用器。在同一个窗口内创建多个 PowerShell、CMD 或 Git Bash 终端。

## 功能

- 不限制固定终端数量，可持续新建终端。
- 自动网格、横向分栏和纵向堆叠布局。
- 单个终端放大/还原。
- 每个终端拥有独立的 ConPTY 会话。
- 可选择新终端的默认工作目录。
- 将文件或文件夹拖入指定终端，可直接输入带引号的完整路径。
- 支持 Codex、Claude、开发服务器和其他交互式命令。
- **SSH 远程终端**：侧栏「远程主机」**连接远程主机…** / 欢迎页 **SSH 远程**，或在设置面板「终端类型」选 SSH 后新建；侧栏列出最近连接的主机，点击即可重连；基于系统 OpenSSH，支持密码与密钥认证，并记住最近连接。
- **Agent 远端桥（MCP）**：SSH 会话可被选为 Agent 工作区，本机 Codex 通过 MCP 读写远端文件、执行远端命令（无需在服务器装 Codex）。
- **Agent 启动台**：标签条 **＋ Agent**（`Ctrl+Shift+L`）检测本机 Claude Code、Codex、Grok、Gemini CLI、Qwen Code、opencode，选好工作目录后一键在新终端启动；未安装的可一键执行 npm 安装。
- **标签页**：每个终端 / Agent 一个标签，标签上显示 Agent 名称与状态；默认「标签页」视图只显示当前终端，也可切回「网格」同时查看全部。
- **Agent 状态显示**：识别终端里运行的 AI CLI，标题栏徽标显示「运行中 / 等待输入 / 需要确认 / 空闲 / 已退出」，底部状态栏汇总数量；后台终端的 Agent 停下等你时可发桌面通知、宠物冒泡提醒。
- **界面布局**：顶栏只保留品牌、标签条、「标签页 / 网格」切换和 **⚙ 设置**；终端类型、Agent 工作区、网格布局、皮肤商城、换背景图、通透度、矩阵宠物、Ultra、Agent MCP 都收在设置面板里（`Esc` 或点空白处关闭）。左侧栏分「工作区 / 会话 / 远程主机」三组：会话列表显示每个终端的 Agent 状态，点击切换、中键关闭。底部状态栏显示当前目录、Git 分支、Agent 汇总、终端数量、视图与终端类型。
- **欢迎页**：启动时（以及关闭全部终端后）显示欢迎页，按时间问候，并列出各 Agent 卡片——已安装的高亮、一键在显示的工作目录里启动，未安装的置灰、点击打开启动台查看安装；下方可新建普通终端、SSH 远程或打开启动台。启动时不再自动新开 PowerShell。
- **字符流动背景**：欢迎页背景是一片缓慢变化的等宽字符网格（A-Z a-z 0-9）：字符低频随机变化，几团亮斑缓慢漂移、照亮经过的字符，夹杂少量皮肤强调色字符，中心渐隐保证卡片可读。详见下文「字符流动背景」。
- **矩阵宠物**：桌面透明置顶小宠物，显示终端数量，可拖动、双击打开主窗口。

## 快捷键

- `Ctrl+Shift+T`：新建终端。
- `Ctrl+Shift+W`：关闭当前终端。
- `Ctrl+Tab` / `Ctrl+Shift+Tab`：切换到下一个 / 上一个标签。
- `Ctrl+1`…`Ctrl+8`：跳到第 N 个标签，`Ctrl+9` 跳到最后一个（没有对应标签时按键照常发给终端）；`Alt+1`…`Alt+9` 仍可用。
- `Ctrl+Shift+L`：打开 / 关闭 Agent 启动台（底部可开关 Agent 桌面通知）。
- `Ctrl+Shift+C`：复制终端选区。
- `Ctrl+Shift+V`：粘贴。
- `Ctrl+Insert` / `Shift+Insert`：复制 / 粘贴。
- 终端内右键：打开复制、粘贴、全选菜单。

## SSH 连接

入口（任选其一）：

1. 左侧边栏「远程主机」**连接远程主机…**（下方列出最近连接，点击直接重连）
2. 欢迎页里的 **SSH 远程**
3. **⚙ 设置** →「终端类型」选 **SSH**，再点标签条 **›_** 新建终端

然后：

1. 填写主机、端口（默认 22）、**用户名**（必填）。
2. **验证方式** 选择：
   - **密码**：填写登录密码（仅存本次内存，可自动应答）
   - **秘钥**：点「加载本地秘钥」或拖入私钥文件；加密私钥再填 **秘钥密码**
   - **每次询问**：在终端里手动输入
3. 可选填写 **Agent 远端根目录**（默认用户主目录）。
4. 连接后在终端内完成主机指纹确认。
5. 最近连接会保存在本机（不含密码 / 秘钥密码），下次可一键回填。

依赖本机 **OpenSSH 客户端**（Windows：设置 → 应用 → 可选功能 → OpenSSH 客户端）。私钥为 OpenSSH / PEM 格式（如 `id_rsa`、`id_ed25519`）。

## Agent 启动台

1. 点击标签条 **＋ Agent**、欢迎页 **启动台…** 或按 `Ctrl+Shift+L`（欢迎页的 Agent 卡片可直接一键启动）。
2. 选择工作目录：默认上次使用的目录；可点 **选择文件夹…**，或从「最近使用」（最多 5 个）中点选。
3. 可选填写 **额外参数**（会追加在命令后，例如 `--model xxx`；不允许 `; & | < > $ %` 等特殊字符）。
4. 已安装的 Agent 点 **启动**：新开一个本地终端，进入所选目录并运行对应命令，标签标题为 Agent 名称。
5. 未安装的 Agent 显示 npm 安装命令，点 **安装** 会在新终端执行 `npm i -g <包名>`（需本机已有 Node.js / npm）；装好后点 **重新检测**。

检测只查找已知安装位置与 `where`（Windows）/ `which` 的结果，不会执行 Agent。命令由主进程按白名单生成。

## 标签页

终端区域顶部是标签条，每个终端（本地、SSH、Agent）一个标签：

- **Agent 标签**显示 Agent 图标、名称和状态（运行中 / 需要确认 / 等待输入 / 空闲 / 已退出）；普通终端显示终端标题。手动在终端里启动的 Agent 也会自动变成 Agent 标签，退出回 shell 后恢复原名。
- **切换**：单击标签，或 `Ctrl+Tab` / `Ctrl+Shift+Tab` / `Ctrl+数字`。
- **关闭**：点 `×` 或鼠标中键；Agent 仍在运行 / 等待时会先确认。
- **重命名**：双击标签，回车确认，Esc 取消，留空恢复默认名称。
- **排序**：拖动标签调整顺序，网格顺序同步变化。
- **新建**：标签条右侧 **＋ Agent** 打开 Agent 启动台；**›_** 新建普通终端。从启动台启动的 Agent 会新开标签并自动切过去；点桌面通知会切到对应标签。
- **提醒**：需要确认的标签即使不在前台也会橙色高亮闪烁；等待输入的后台标签有淡色描边。标签多时可横向滚动（支持鼠标滚轮）。
- **显示方式**：顶栏 **标签页 / 网格** 切换并记住选择，默认「标签页」。标签页模式下只显示当前终端并铺满，其他终端在后台继续运行（不会重建），切回时自动适配尺寸；设置面板里的「网格布局」只在网格模式下生效。

## Agent 状态显示

终端矩阵会识别每个终端（本地或 SSH）里前台运行的 AI CLI：

- **识别方式**：从启动台 / SSH「连接后启动 Agent」打开的会话直接识别；手动输入 `claude`、`codex`、`gemini`、`qwen`、`grok`、`opencode`（含 `.cmd`/`.exe`、完整路径、`npx <包名>`）也会识别；部分 Agent 的启动横幅（如 “Welcome to Claude Code”、“OpenAI Codex”）作为补充。
- **状态**（终端标题栏徽标）：
  - **运行中**：近 2.5 秒内有输出（思考、流式输出），绿点呼吸动画。
  - **需要确认**：输出停下且末尾像确认提示（`Do you want to`、`Allow …?`、`(y/n)`、`❯ 1. Yes`、`Press Enter`、`Approve`、`是否继续` 等），橙色闪烁。
  - **等待输入**：输出停下，Agent 在等你下一条指令。
  - **空闲**：等待超过 5 分钟，或启动后一直没有输出。
  - **已退出**：终端进程退出，显示退出代码。
  - Agent 退出回到 shell 提示符（`PS C:\…>`、`C:\…>`、`$`、`user@host:~$`）后徽标自动消失。
- **汇总**：底部状态栏显示如「2 个 Agent 运行中 · 1 个需要确认」；左侧「会话」列表每行也有状态圆点。
- **桌面通知**：Agent 从「运行中」停到「等待输入 / 需要确认」，且主窗口不在前台或该终端不是当前终端时，发送系统通知（同一终端 15 秒内最多一次），点通知会切回该终端；矩阵宠物开启时也会冒泡提醒。开关在 **Agent 启动台** 底部，默认开启并记住选择。

检测只分析输出尾部（去掉 ANSI 序列后保留约 2 KB），每 0.5 秒统一评估一次，不会拖慢终端输出。判断是启发式的，个别 TUI 可能出现误判。

## 本地 Agent 操作远端（MCP）

终端矩阵可将本地运行的 Codex、Grok 或 Claude Code 连接到现有 SSH 会话，远端无需安装任何 Agent：

1. 打开 **SSH 连接**，选择密码或秘钥登录；密码 / 秘钥密码只保存在本次应用运行的内存中，不写入最近连接。
2. 开启 **连接后启动 Agent**。终端矩阵会自动检测本机的 Codex、Grok 和 Claude Code，只允许选择已经安装且可运行的 Agent。
3. 点击 **连接并启动**。SSH 会话建立后，终端矩阵会自动完成本机 MCP 注册，并在右侧终端直接启动所选 Agent。
4. 在右侧 Agent 终端输入开发任务；Agent 将通过 `remote_connection_info`、`remote_list`、`remote_stat`、`remote_read`、`remote_exec`、`remote_write`、`remote_mkdir` 操作左侧 SSH 对应的远端工作区。

**⚙ 设置** 面板里的 **Agent MCP** 和 **Agent 工作区** 仍保留，供手动补配、切换远端会话或高级多终端场景使用。

注册过程只配置用户已经安装的 Agent，不会向远端上传 Codex、Grok 或 Claude Code。Windows 版使用终端矩阵内置运行时启动 MCP 服务，用户无需另外安装 Node.js。若 Agent 会话在注册前已经启动，请刷新 MCP 或重新启动该会话。

MCP 桥接进程在本机运行，通过终端矩阵主进程持有的 SSH/SFTP 连接操作远端。远端路径默认限制在登录用户主目录（`root` 默认 `/root`），可在 SSH 对话框中调整。`remote_exec` 和写入工具会被标记为可能修改远端，便于 MCP 客户端按策略请求确认。

## 字符流动背景

在 **⚙ 设置 →「外观」** 中调整，设置会被记住：

- **字符流动背景**：开关，默认开启。
- **应用范围**：「仅欢迎页」（默认）或「欢迎页 + 终端背景」。后者会把终端区改成半透明，字符背景以很低的亮度垫在终端文字下面。
- **强度**：淡 / 中 / 强，影响亮度、亮斑数量和字符变化速度。

皮肤适配：

- 深色皮肤：浅色字符，强调色取自皮肤的 `--accent-bright`。
- 浅色皮肤（如纸白）：自动改为浅底上的深灰字符，并整体调淡。
- 图片皮肤：以背景图为准，不显示字符背景；换回纯色皮肤后自动恢复。

性能：

- 用一个 canvas 绘制，适配 `devicePixelRatio`，窗口缩放时自动重建网格。
- 只重画亮度档、字符或颜色变化了的格子。
- 欢迎页约 20fps，终端背景约 15fps，窗口失焦时降到 6～8fps。
- 窗口最小化或隐藏、欢迎页不可见、关闭开关时完全停止。
- 系统开启「减少动态效果」（`prefers-reduced-motion`）时只画一帧静态画面。

实现见 `renderer/char-field.js`（纯逻辑可在 Node 中测试，`scripts/char-field-smoke.js`）和 `renderer/char-field-ui.js`（设置与挂载）。

## 换皮（皮肤商城）

**⚙ 设置** →「外观」→ **皮肤商城** 可浏览、搜索、分类筛选并一键应用皮肤。

- **纯色主题**：矩阵绿 / 午夜蓝 / 赛博紫 / 余烬橙 / 纸白浅色
- **背景模板**：在 `renderer/skins/catalog.js` 配置，图片放 `renderer/skins/`
- **本地换图**：商城内选本机图片，自动切到自定义图片皮肤并记住
- **通透**：图片皮肤下可调面板透明度；调低更易见背景，调高更易读终端
- 通透度滑块与「换背景图」也在设置面板「外观」组

详见 `renderer/skins/README.md`。

## 打包与发布（重要）

**不要把 `release/` 安装包提交进 Git。**  
Electron 安装包约几十～上百 MB，会超过 Git 单文件限制，也极易上传失败。  
`release/` 已在 `.gitignore` 中。

### 本地打包

```powershell
# 默认：只打便携版（体积更小，一个文件）
npm run dist:win

# 需要安装包时
npm run dist:win:setup

# 安装包 + 便携版
npm run dist:win:all
```

产物目录：`release/`

| 命令 | 产物 |
|------|------|
| `npm run dist:win` | `terminal-deck-portable-v*-windows-x64.exe` |
| `npm run dist:win:setup` | `terminal-deck-setup-v*-windows-x64.exe` |

### 发布到 GitHub Releases（推荐）

本地网络上传大文件容易失败，**推荐用 GitHub Actions 在云端打包并上传**：

```powershell
# 1. 改版本号（package.json 的 version）
# 2. 提交代码并打 tag
git add .
git commit -m "release: v0.1.1"
git tag v0.1.1
git push origin main
git push origin v0.1.1
```

推送 `v*` 标签后，`.github/workflows/release.yml` 会自动：

1. 在 Windows 云主机上 `npm run dist:win`
2. 创建 / 更新 GitHub Release
3. 挂上 `terminal-deck-portable-*.exe`

也可在 GitHub 仓库 **Actions → Release → Run workflow** 手动触发。

### 体积优化说明

- 只保留 `en-US` / `zh-CN` 语言包  
- 打包后剔除 node-pty 的 macOS / ARM 预编译  
- 默认只打便携版一个文件（避免装包+便携双份上传）
